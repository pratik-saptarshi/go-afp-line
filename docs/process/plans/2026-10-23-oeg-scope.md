# OEG Scope Guard Plan — v2 (wringer-refined)

**Goal:** Prevent MCFs carried inside Object Environment Groups from polluting the page-scoped font map, with minimal code and zero behavior change on valid inputs. An MCF inside an OEG is still parsed (fail-closed on malformed input) but its mapping is discarded instead of merged into the page namespace.

**Architecture:** A boolean `inOEG` on `reduceState`. `visitRaw` intercepts BOG (`D3A8C7`) and EOG (`D3A9C7`) before the `t.Excluded` early-return: BOG sets `inOEG = true`, EOG sets `inOEG = false`, then execution falls through to the existing exclusion path (BOG/EOG stay in the excluded-IDs table and the exclusions census — no manual recording, no double-count). The `D3AB8A` (MCF) case gains one guard: if `inOEG`, parse via `afp.ParseMCFMapping` (with the existing offset rebase; malformed input still aborts loudly) but discard the result instead of merging. `inOEG` is cleared at BDT, BPG, and EPG: an OEG cannot span a document or page boundary, so any open OEG scope ends there (mirroring the `st.mcf` resets at BDT/BPG).

Why a boolean, not a stack: OEGs wrap excluded objects — v1 does not process objects, so OEG internal structure (nesting, pairing) is out-of-subset content whose validation would be gold-plating. The boolean closes the actual hole (scope pollution / false duplicate-LID aborts) in ~15 lines with zero dead code: no `grpOEG` stack member, no unconsulted maps, no contract §9 change. An unclosed BOG is conservatively fail-closed: `inOEG` stays true and all subsequent MCFs are parsed-but-discarded rather than merged into the wrong scope. BOG inside an open page is explicitly allowed (real files do this — OEGs wrap objects that live on pages); no position rejection.

**Tech Stack:** Go 1.27, stdlib only.

**Spec:** `docs/subset-contract.md` §9 (BOG/EOG excluded; all object types excluded); MO:DCA Reference §"Begin/End Object Environment Group" (BOG `D3A8C7`, EOG `D3A9C7`; OEG wraps a single object and its environment).
